Deep Agents Code 将其配置存储在 `~/.deepagents/` 目录中。主要配置文件如下：

| 文件 | 格式 | 用途 |
|------|------|------|
| `config.toml` | TOML | 模型默认值、提供商设置、构造函数参数、配置文件覆盖、主题、更新设置、MCP 信任存储 |
| `.env` | Dotenv | 全局 API 密钥和密钥 |
| `hooks.json` | JSON | Deep Agents Code 生命周期事件的外部工具订阅 |
| `.mcp.json` | JSON | 全局 MCP 服务器定义 |

<Note>
    `~/.deepagents/.state/` 下的文件保存每台机器的 Deep Agents Code 状态，并自动管理。
</Note>

## 提供商凭据

对于每个提供商，Deep Agents Code 按顺序检查两个凭据来源：

1. **存储的密钥**——通过 `/auth` 输入并在本地持久化。
2. **环境变量**——`OPENAI_API_KEY`、`ANTHROPIC_API_KEY`、`GOOGLE_API_KEY` 等，以及带有 [`DEEPAGENTS_CODE_`](#deepagents_code_-prefix) 前缀的相同名称和从 [`.env` 文件](#environment-variables) 加载的任何密钥。

对于同一个提供商，存储的密钥始终优先于环境变量密钥。

### 使用 `/auth`（推荐）

从任何会话中打开凭据管理器：

```txt
/auth
```

管理器列出 Deep Agents Code 知道的所有 LLM 提供商，标记已拥有密钥的提供商，并允许你内联粘贴、轮换或清除凭据。每个提供商呈现为以下之一：

| 标签 | 含义 |
|------|------|
| `✓ credentials set` | 存储的密钥或环境变量密钥可用 |
| `! missing OPENAI_API_KEY` | 命名的环境变量未设置且没有存储的密钥——选择该行以粘贴一个 |
| `local provider` | 不需要凭据（例如本地 Ollama） |
| `implicit auth` | 凭据是隐式的（例如 Vertex AI 应用程序默认凭据） |
| `custom auth` | 管理自身认证的 `class_path` 提供商（mTLS、JWT、自定义标头） |

在行上按 Enter 粘贴密钥，或使用行的删除功能清除现有密钥。保存的密钥被原子性地写入，并在会话和 `/reload` 之间持久存在。

<Note>
    密钥限定为此机器上的用户账户——Deep Agents Code 绝不会将其传输到已配置提供商的 API 以外的任何地方。
</Note>

`/auth` 仅管理 **LLM 提供商**凭据。像 `TAVILY_API_KEY`（网络搜索）和 `LANGSMITH_API_KEY`（追踪）这样的工具凭据是从环境中读取的——[在 `~/.deepagents/.env` 或你的 shell 中设置它们](#environment-variables)。

### 环境变量（CI 和无头模式）

对于非交互式运行、CI/CD 管道或在没有 TUI 的任何地方，导出提供商的 env 变量或将其写入 `~/.deepagents/.env`：

```bash
export ANTHROPIC_API_KEY="sk-ant-..."
export OPENAI_API_KEY="sk-..."
```

参见下面的[环境变量](#environment-variables)了解加载顺序、`DEEPAGENTS_CODE_` 前缀和按项目覆盖。

## 环境变量

Deep Agents Code 从 dotenv 文件加载环境变量，因此你无需在 shell 配置文件中 `export` API 密钥或在项目中复制 `.env` 文件。

### 加载顺序与优先级

启动时加载两个 `.env` 文件：

1. **项目 `.env`**——当前工作目录中的 `.env` 文件（如果存在）
2. **全局 `~/.deepagents/.env`**——作为所有项目回退的单个共享文件

有效优先级为：**shell 环境 > 项目 `.env` > 全局 `.env`**。已在 shell 中设置的值永远不会被覆盖——包括在 `/reload` 时。

### `DEEPAGENTS_CODE_` 前缀

所有 Deep Agents Code 特定的环境变量都使用 `DEEPAGENTS_CODE_` 前缀（例如 `DEEPAGENTS_CODE_AUTO_UPDATE`、`DEEPAGENTS_CODE_DEBUG`）。参见[环境变量参考](#environment-variable-reference)获取完整列表。

此前缀也可作为 Deep Agents Code 读取的任何环境变量的覆盖机制，包括第三方凭据。Deep Agents Code 首先检查 `DEEPAGENTS_CODE_{NAME}`，然后回退到 `{NAME}`：

```bash title="~/.deepagents/.env"
# 仅对 Deep Agents Code 覆盖 OPENAI_API_KEY，不影响其他工具
DEEPAGENTS_CODE_OPENAI_API_KEY=sk-cli-only

# 通过将前缀变量设置为空来阻止 shell 导出的密钥在 Deep Agents Code 中使用
DEEPAGENTS_CODE_ANTHROPIC_API_KEY=
```

在 `/reload` 时，Deep Agents Code 重新读取 `.env` 文件并获取带前缀的值，因此你可以在不重启的情况下轮换密钥。

### 示例

将 API 密钥一次性存储在 `~/.deepagents/.env` 中：

```bash
ANTHROPIC_API_KEY=sk-ant-...
OPENAI_API_KEY=sk-...
LANGSMITH_API_KEY=lsv2_...
TAVILY_API_KEY=tvly-...

# 如果 OPENAI_API_KEY 已在 shell 中为其他工具导出，
# 使用前缀为 Deep Agents Code 提供自己的密钥而不冲突
DEEPAGENTS_CODE_OPENAI_API_KEY=sk-cli-only-...
```

然后在需要时通过在项目目录中放置 `.env` 来按项目覆盖。

### 使用 Tavily 启用网络搜索

内置的 `web_search` 工具使用 [Tavily](https://tavily.com)。Deep Agents Code 在启动时会显示"Web search disabled — `TAVILY_API_KEY` is not set"通知，直到你提供密钥。与模型提供商密钥不同，Tavily **不**由 `/auth` 管理；它直接从环境读取。

<Steps>
    <Step title="获取密钥">
        在 [tavily.com](https://tavily.com) 注册并复制密钥（以 `tvly-` 开头）。免费套餐足以满足大多数 Deep Agents Code 使用场景。
    </Step>

    <Step title="将其添加到环境中">
        将密钥添加到 `~/.deepagents/.env`，这样每次会话都能获取到它：

        ```bash title="~/.deepagents/.env"
        TAVILY_API_KEY=tvly-...
        ```

        或者在 shell 中导出用于一次性会话：

        ```bash
        export TAVILY_API_KEY=tvly-...
        ```

        Shell 导出优先于 `.env` 值（参见[加载顺序与优先级](#loading-order-and-precedence)）。要将密钥仅限定在 Deep Agents Code 范围内而不影响读取 `TAVILY_API_KEY` 的其他工具，请使用 [`DEEPAGENTS_CODE_` 前缀](#deepagents_code_-prefix)：`DEEPAGENTS_CODE_TAVILY_API_KEY=tvly-...`。
    </Step>

    <Step title="重新加载或重启">
        在现有会话中，运行 `/reload` 重新读取 `.env` 文件。下次启动时，"Web search disabled"通知消失，智能体可以调用 `web_search`。
    </Step>
</Steps>

## 配置文件

`~/.deepagents/config.toml` 允许你自定义模型提供商、设置默认值以及向模型构造函数传递额外参数。

### 默认模型与最近模型

```toml
[models]
default = "ollama:qwen3:4b"             # 你明确的长偏好
recent = "google_genai:gemini-3.5-flash"   # 上次 /model 切换（自动写入）
```

`[models].default` 始终优先于 `[models].recent`。`/model` 命令仅写入 `[models].recent`，因此你配置的默认值永远不会被会话中的切换覆盖。要移除默认值，请使用 `/model --default --clear` 或从配置文件中删除 `default` 键。

### 默认智能体与最近智能体

```toml
[agents]
default = "backend-dev"  # 你明确的长偏好（在 /agents 选择器中按 Ctrl+S）
recent = "frontend-dev"  # 上次 /agents 切换（自动写入）
```

`[agents].default` 始终优先于 `[agents].recent`。在 `/agents` 选择器中按 `Enter` 选择智能体会写入 `recent`；在突出显示的行上按 `Ctrl+S` 会将其固定为 `default`。在同一行上再次按 `Ctrl+S` 会清除默认值。

显式的 `-a`/`--agent` 始终覆盖两者，而 `-r`/`--resume` 绕过两者，从而恢复线程的原始智能体。参见[命令参考](/zh/oss/deepagents/code/overview#command-reference)了解相关标志。

### 提供商配置

每个提供商是 `[models.providers]` 下的一个 TOML 表：

```toml
[models.providers.<name>]
models = ["gpt-4o"]
api_key_env = "OPENAI_API_KEY"
base_url = "https://api.openai.com/v1"
class_path = "my_package.models:MyChatModel"
enabled = true

[models.providers.<name>.params]
temperature = 0
max_tokens = 4096

[models.providers.<name>.params."gpt-4o"]
temperature = 0.7
```

提供商具有以下配置选项：

<ResponseField name="models" type="string[]" post={["可选"]}>
    要在此提供商的交互式 `/model` 切换器中显示的模型名称列表。对于已附带模型配置文件的提供商，你在此添加的任何名称都会与捆绑的模型一起出现，适用于尚未添加到包中的新发布模型。对于[任意提供商](#arbitrary-providers)，此列表是切换器中模型的唯一来源。

    在此列出的模型**绕过**基于配置文件的[过滤标准](/zh/oss/deepagents/code/providers#which-models-appear-in-the-switcher)，并始终出现在切换器中。这使得它成为展示因配置文件缺少 `tool_calling` 支持或尚不存在而被排除的模型的首选方式。

    此键是可选的。你始终可以将任何模型名称直接传递给 `/model` 或 `--model`，无论它是否出现在切换器中；提供商会在请求时验证名称。
</ResponseField>

<ResponseField name="api_key_env" type="string" post={["可选"]}>
    保存 API 密钥的**环境变量名称**（例如 `"OPENAI_API_KEY"`），而非密钥本身。Deep Agents Code 在启动时从此 env 变量读取凭据，以在创建模型前验证访问权限。大多数聊天模型包会自动从默认的 env 变量读取。参见[提供商参考](/zh/oss/deepagents/code/providers#provider-reference)表格了解每个提供商检查的变量。
</ResponseField>

<ResponseField name="base_url" type="string" post={["可选"]}>
    覆盖提供商使用的基础 URL（如果支持）。有关更多信息，请参阅提供商包的[参考文档](https://reference.langchain.com/python/integrations/)。
</ResponseField>

<ResponseField name="params" type="object" post={["可选"]}>
    转发给模型构造函数的额外关键字参数。扁平键（例如 `temperature = 0`）适用于该提供商的所有模型。模型键子表（例如 `[params."gpt-4o"]`）仅覆盖该模型的个别值；合并是浅层的（冲突时模型胜出）。

    不要将凭据（例如 `api_key`）放在 `params` 中。请使用 [`api_key_env`](#provider-configuration) 指向环境变量。
</ResponseField>

<ResponseField name="profile" type="object" post={["可选"]}>
    （高级）覆盖模型运行时[配置文件](/zh/oss/langchain/models#model-profiles)中的字段（例如 `max_input_tokens`）。扁平键适用于该提供商的所有模型。模型键子表（例如 `[profile."claude-sonnet-4-5"]`）仅覆盖该模型的个别值；合并是浅层的（冲突时模型胜出）。这些覆盖在模型创建后应用，因此它们对上下文限制显示、自动摘要和其他读取配置文件的特性生效。
</ResponseField>

<ResponseField name="class_path" type="string" post={["可选"]}>
    用于[任意模型](#arbitrary-providers)提供商。完全限定的 Python 类，格式为 `module.path:ClassName`。设置后，Deep Agents Code 直接导入并实例化此类的提供商 `<name>`。该类必须是 `BaseChatModel` 子类。
</ResponseField>

<ResponseField name="enabled" type="boolean" default="true" post={["可选"]}>
    此提供商是否出现在 `/model` 选择器中。设置为 `false` 以隐藏从已安装包自动发现的提供商（例如你不想让切换器混乱的传递依赖项）。你仍然可以通过 `/model provider:model` 或 `--model` 直接使用禁用的提供商。
</ResponseField>

### 模型构造函数参数

任何提供商都可以使用 `params` 表向模型构造函数传递额外参数：

```toml
[models.providers.ollama.params]
temperature = 0
num_ctx = 8192
```

#### 按模型覆盖

如果特定模型需要不同的参数，在 `params` 下添加一个模型键子表以覆盖个别值，无需复制整个提供商配置：

```toml
[models.providers.ollama]
models = ["qwen3:4b", "llama3"]

[models.providers.ollama.params]
temperature = 0
num_ctx = 8192

[models.providers.ollama.params."qwen3:4b"]
temperature = 0.5
num_ctx = 4000
```

使用此配置：

* `ollama:qwen3:4b` 获得 `{temperature: 0.5, num_ctx: 4000}`——模型覆盖胜出。
* `ollama:llama3` 获得 `{temperature: 0, num_ctx: 8192}`——无覆盖，仅提供商级别参数。

合并是浅层的：模型子表中存在的任何键都会替换提供商级别参数中的相同键，而仅在提供商级别的键则保留。

<Tip>
    要进行一次性调整而无需编辑 `config.toml`，请在启动时通过 `--model-params` 传递 JSON 对象，或在会话中通过 `/model` 传递。CLI 标志的优先级高于配置文件。参见提供商页面上的[模型参数](/zh/oss/deepagents/code/providers#model-parameters)了解语法和提供商特定示例。
</Tip>

### 配置文件覆盖（高级）

覆盖模型运行时配置文件中的字段，以更改 Deep Agents Code 解释模型能力的方式。最常见的用例是降低 `max_input_tokens` 以更早触发自动摘要——对于测试或限制上下文使用非常有用：

```toml
# 应用于此提供商的所有模型
[models.providers.anthropic.profile]
max_input_tokens = 4096
```

按模型子表的工作方式与 `params` 相同——冲突时模型级别的值胜出：

```toml
[models.providers.anthropic.profile]
max_input_tokens = 4096

# 此模型获得更高的限制
[models.providers.anthropic.profile."claude-sonnet-4-5"]
max_input_tokens = 8192
```

配置文件覆盖在创建后合并到模型的配置文件中。任何读取配置文件的特性——状态栏中的上下文限制显示、自动摘要阈值、能力检查——都会看到覆盖后的值。

#### CLI 配置文件覆盖与 `--profile-override`（高级）

要在不编辑配置文件的情况下在运行时覆盖模型配置字段，通过 `--profile-override` 传递 JSON 对象：

```bash
dcode --profile-override '{"max_input_tokens": 4096}'

# 与 --model 组合
dcode --model google_genai:gemini-3.5-flash --profile-override '{"max_input_tokens": 4096}'

# 在非交互模式下
dcode -n "总结此仓库" --profile-override '{"max_input_tokens": 4096}'
```

这些在配置文件覆盖之上合并（CLI 胜出）。优先级链为：模型默认值 &lt; config.toml 配置文件 &lt; CLI `--profile-override`。

`--profile-override` 值在会话中的 `/model` 热切换之间保持不变——切换模型会将覆盖重新应用于新模型。

### 自定义基础 URL

某些提供商包接受 `base_url` 来覆盖默认端点。例如，`langchain-ollama` 通过底层 `ollama` 客户端默认为 `http://localhost:11434`。要指向其他位置，在配置中设置 `base_url`：

```toml
[models.providers.ollama]
base_url = "http://your-host-here:port"
```

请参阅提供商参考文档以了解兼容性信息和其他注意事项。

### 兼容 API

对于公开与 OpenAI 或 Anthropic 兼容 API 的提供商，你可以使用现有的 `langchain-openai` 或 `langchain-anthropic` 包，方法是将 `base_url` 指向提供商的端点：

```toml
[models.providers.openai]
base_url = "https://api.example.com/v1"
api_key_env = "EXAMPLE_API_KEY"
models = ["my-model"]
```

```toml
[models.providers.anthropic]
base_url = "https://api.example.com"
api_key_env = "EXAMPLE_API_KEY"
models = ["my-model"]
```

<Note>
    提供商在官方规范之上添加的任何功能将不会被捕获。如果提供商提供了专用的 LangChain 集成包，请优先使用该包。
</Note>

<Warning>
    OpenAI 提供商默认使用 [Responses API](https://platform.openai.com/docs/api-reference/responses)，大多数 OpenAI 兼容网关未实现该 API。如果你的提供商仅支持 Chat Completions API，调用可能会失败。显式禁用 Responses API：

    ```toml
    [models.providers.openai.params]
    use_responses_api = false
    ```
</Warning>

### 向交互式切换器添加模型

某些提供商（例如 `langchain-ollama`）不捆绑模型配置文件数据（参见[提供商参考](/zh/oss/deepagents/code/providers#provider-reference)获取完整列表）。在这种情况下，交互式 `/model` 切换器不会列出该提供商的模型。你可以通过在配置文件中为提供商定义 `models` 列表来填补这一空白：

```toml
[models.providers.ollama]
models = ["llama3", "mistral", "codellama"]
```

现在 `/model` 切换器将包含一个带有这些模型的 Ollama 部分。

这完全是可选的。你始终可以通过直接指定完整名称来切换到任何模型：

```txt
/model ollama:llama3
```

<Note>
    当安装了 `langchain-ollama` 且守护进程可达时，Deep Agents Code 会自动发现本地拉取的模型并将其合并到切换器中——无需 `models` 列表。拉取新模型后运行 `/reload` 刷新，或设置 `DEEPAGENTS_CODE_OLLAMA_DISCOVERY=0` 选择退出。
</Note>

### 任意提供商

你可以使用任何 [LangChain `BaseChatModel`](https://reference.langchain.com/python/langchain_core/language_models/#langchain_core.language_models.BaseChatModel) 子类，使用 `class_path`。Deep Agents Code 直接导入并实例化该类——无需内置提供商包。

```toml
[models.providers.my_custom]
class_path = "my_package.models:MyChatModel"
api_key_env = "MY_API_KEY"
base_url = "https://my-endpoint.example.com"

[models.providers.my_custom.params]
temperature = 0
max_tokens = 4096
```

`api_key_env` 和 `base_url` 是可选的。`class_path` 提供商预计自行处理内部认证——适用于你的模型使用自定义认证（JWT 令牌、专有标头、mTLS 等）而非标准 API 密钥的情况：

```toml
[models.providers.xyz]
class_path = "abc.integrations.deepagents:DeepAgentsXYZChat"
models = ["abc-xyz-1"]

[models.providers.xyz.params]
bypass_auth = true
temperature = 0
```

使用此配置，通过 `/model xyz:abc-xyz-1` 或 `--model xyz:abc-xyz-1` 切换到模型。

<Note>
    Deep Agents Code 需要**工具调用**支持。如果你的自定义模型支持工具调用但 Deep Agents Code 不知道，请在提供商配置文件中声明：

    ```toml
    [models.providers.xyz.profile]
    tool_calling = true
    max_input_tokens = 128000
    ```

    将 `max_input_tokens` 设置为你模型支持的值，以启用准确的上下文长度跟踪和自动摘要。
</Note>

提供商包必须安装在与 `deepagents-code` 相同的 Python 环境中：

```bash
# 如果 deepagents-code 通过 uv tool 安装：
uv tool install deepagents-code --with my_package
```

当你切换到 `my_custom:my-model-v1`（通过 `/model` 或 `--model`）时，模型名称（`my-model-v1`）作为 `model` kwarg 传递：

```python
MyChatModel(model="my-model-v1", base_url="...", api_key="...", temperature=0, max_tokens=4096)
```

<Warning>
    `class_path` 从你的配置文件中执行任意 Python 代码。这与 `pyproject.toml` 构建脚本具有相同的信任模型——你控制你自己的机器。
</Warning>

你的提供商包可以选择在 `<package>.data._profiles` 的 `_PROFILES` dict 中提供模型配置文件，而非在 `models` 键下定义。有关更多信息，请参见 LangChain [模型配置文件](https://github.com/langchain-ai/langchain/tree/master/libs/model-profiles)。

## 技能额外允许目录

默认情况下，当 Deep Agents Code 加载技能时，它会验证解析后的技能文件路径是否保持在标准[技能目录](/zh/oss/deepagents/code/data-locations#skills)之一内。这可以防止技能目录内的符号链接读取这些根目录外的任意文件。

如果你将共享技能资产存储在非标准位置，并通过标准技能目录的符号链接引用它们，你可以将该位置添加到包含允许列表。这**不**会添加新的技能发现位置：技能仍然仅从标准目录发现。

<ResponseField name="extra_allowed_dirs" type="string[]" post={["可选"]}>
    添加到技能包含允许列表的路径。支持 `~` 展开。

    ```toml
    [skills]
    extra_allowed_dirs = [
        "~/shared-skills",
        "/opt/team-skills",
    ]
    ```
</ResponseField>

或者，将 `DEEPAGENTS_CODE_EXTRA_SKILLS_DIRS` 环境变量设置为冒号分隔的列表：

```bash
export DEEPAGENTS_CODE_EXTRA_SKILLS_DIRS="~/shared-skills:/opt/team-skills"
```

当设置了环境变量时，它优先于配置文件值。更改在 `/reload` 时生效。

## 主题

使用 `/theme` 打开交互式主题选择器。浏览列表以实时预览主题，按 `Enter` 将你的选择持久化到 `config.toml`。

Deep Agents Code 附带许多内置主题。默认主题是 `langchain`，这是一个使用 LangChain 品牌色的深色主题。所选主题在 `[ui]` 下持久化：

```toml
[ui]
theme = "langchain-dark"
```

### 用户定义的主题

在 `config.toml` 的 `[themes.<name>]` 部分下定义自定义主题。每个部分需要 `label`（字符串）。`dark`（布尔值）如果省略则默认为 `false`——设置为 `true` 用于深色主题。所有颜色字段都是可选的——省略的字段根据 `dark` 标志回退到内置的深色或浅色调色板。

```toml
[themes.my-solarized]
label = "My Solarized"
dark = true
primary = "#268BD2"
warning = "#B58900"

# 带空格的主题名称需要 TOML 引号
[themes."ocean breeze"]
label = "Ocean Breeze"
primary = "#0077B6"
background = "#CAF0F8"
```

用户定义的主题会与内置主题一起出现在 `/theme` 选择器中。

### 覆盖内置主题颜色

要调整内置主题的颜色而不创建新主题，使用 `[themes.<builtin-name>]` 部分。仅读取颜色字段——`label` 和 `dark` 继承自内置主题：

```toml
[themes.langchain]
primary = "#FF5500"
```

省略的颜色字段保留现有的内置值。

对 `[themes.*]` 部分的更改在 `/reload` 时生效。

### 将主题映射到终端

如果你在不同颜色方案的终端之间切换（例如深色 iTerm 和浅色 Apple Terminal），将每个终端映射到 `[ui.terminal_themes]` 下的一个主题。Deep Agents Code 匹配 shell 的 `TERM_PROGRAM` 并自动应用映射的主题：

```toml
[ui.terminal_themes]
"Apple_Terminal" = "langchain-light"
"iTerm.app" = "langchain"
```

在 `/theme` 选择器中按 `T` 为当前终端保存高亮的主题，或运行 `echo $TERM_PROGRAM` 查找终端标识符并手动添加。

<Accordion title="高级：选择器快捷键、解析顺序、终端标识符">
    #### 选择器快捷键

    在 `/theme` 选择器中：

    - `N` 切换显示标签和规范注册键——键是 `[ui] theme` 和 `[ui.terminal_themes]` 接受的格式。
    - `T` 将高亮的主题保存到当前 `TERM_PROGRAM` 的 `[ui.terminal_themes]` 中。映射的主题在选择器中会标记 `（默认）`。

    #### 常见 `TERM_PROGRAM` 值

    键与环境变量完全匹配——当它们包含点或特殊字符时在 TOML 中加引号。

    | 终端 | `TERM_PROGRAM` |
    | --- | --- |
    | Apple Terminal | `Apple_Terminal` |
    | iTerm2 | `iTerm.app` |
    | WezTerm | `WezTerm` |
    | VS Code 集成终端 | `vscode` |
    | Ghostty | `ghostty` |

    #### 解析顺序

    Deep Agents Code 在每次启动时使用以下优先级解析主题：

    1. `DEEPAGENTS_CODE_THEME` 环境变量（显式覆盖）。
    2. 当前 `TERM_PROGRAM` 的 `[ui.terminal_themes]` 映射。
    3. 通过 `/theme` 保存的 `[ui] theme` 偏好。
    4. 内置默认值（`langchain`）。
</Accordion>

## 自动更新

Deep Agents Code 可以自动检查并安装更新。

<Tabs>
    <Tab title="配置文件">
        ```toml
        [update]
        auto_update = true
        ```
    </Tab>
    <Tab title="环境变量">
        ```bash
        export DEEPAGENTS_CODE_AUTO_UPDATE=1
        ```
    </Tab>
</Tabs>

环境变量优先于配置文件。

启用后，Deep Agents Code 在会话启动时检查 PyPI 是否有较新版本，并使用检测到的安装方法（uv、Homebrew 或 pip）自动升级。禁用时（默认），Deep Agents Code 会显示更新提示及相应的安装命令。

你也可以随时使用 `/update` 斜杠命令手动检查并安装更新，该命令绕过缓存并内联报告成功或失败。

升级后，Deep Agents Code 会在下次启动时显示"新内容"横幅，其中包含更新日志的链接。

在会话退出时，如果会话期间检测到较新版本，会显示更新横幅作为提醒。

## 托管部署

[安装脚本](https://github.com/langchain-ai/deepagents/blob/main/libs/cli/scripts/install.sh)支持以 root 身份运行，针对在最小 root 环境中执行脚本的 macOS MDM 工具（Kandji、Jamf 等）。

当 `id -u` 为 `0` 时，脚本：

1. 解析实际控制台用户的 `HOME`（通过 `/dev/console` 或 `/Users` 目录扫描）
2. 在每个安装步骤后将创建的所有文件 `chown` 回目标用户

非 root 安装不受影响：所有 root 特定的代码路径在非 root 运行时都会短路。

要为托管安装预配置自动更新，在用户的 shell 配置文件中设置 `DEEPAGENTS_CODE_AUTO_UPDATE=1`，或部署带有 `[update] auto_update = true` 的 `config.toml` 到 `~/.deepagents/config.toml`。要完全抑制自动更新和更新检查，设置 `DEEPAGENTS_CODE_NO_UPDATE_CHECK=1`。

## 外部编辑器

按 `Ctrl+X` 或输入 `/editor` 在外部编辑器中撰写提示。Deep Agents Code 检查 `$VISUAL`，然后检查 `$EDITOR`，然后回退到 `vi`（macOS/Linux）或 `notepad`（Windows）。GUI 编辑器（VS Code、Cursor、Zed、Sublime Text、Windsurf）会自动接收 `--wait` 标志，以便 Deep Agents Code 阻塞直到你关闭文件。

```bash
# 在 shell 配置文件中设置（~/.zshrc、~/.bashrc 等）
export VISUAL="code"    # GUI 编辑器（自动注入 --wait）
export EDITOR="nvim"    # 终端回退
```

## 钩子

钩子允许外部程序响应 Deep Agents Code 的生命周期事件。在 `~/.deepagents/hooks.json` 中配置命令，每当事件触发时，它会将 JSON 负载通过管道发送到每个匹配命令的 stdin。

钩子在后台线程中以即发即弃方式运行——它们永远不会阻塞 Deep Agents Code，失败时会被记录而不会中断你的会话。

### 设置

创建 `~/.deepagents/hooks.json`：

```json
{
  "hooks": [
    {
      "command": ["bash", "-c", "cat >> ~/deepagents-events.log"],
      "events": ["session.start", "session.end"]
    }
  ]
}
```

现在每次会话开始或结束时，Deep Agents Code 都会将事件负载追加到 `~/deepagents-events.log`。

### 钩子配置

配置文件包含一个 `hooks` 数组。每个条目包含：

<ResponseField name="command" type="list[str]" required>
    要运行的命令和参数。不进行 shell 展开：如果需要，使用 `["bash", "-c", "..."]`。
</ResponseField>

<ResponseField name="events" type="list[str]" post={["可选"]}>
    要订阅的事件名称。省略或留空以接收**所有**事件。
</ResponseField>

```json
{
  "hooks": [
    {
      "command": ["python3", "my_handler.py"],
      "events": ["session.start", "task.complete"]
    },
    {
      "command": ["bash", "log_everything.sh"]
    }
  ]
}
```

上面的第二个钩子没有 `events` 过滤器，因此它接收 Deep Agents Code 发出的每个事件。

### 负载格式

每个钩子命令在 stdin 上接收一个 JSON 对象，包含 `"event"` 键以及事件特定字段：

```json
{
  "event": "session.start",
  "thread_id": "abc123"
}
```

### 事件参考

#### `session.start`

在智能体会话开始时触发（交互和非交互模式均适用）。

<ResponseField name="thread_id" type="string" required>
    会话线程标识符。
</ResponseField>

#### `session.end`

在会话退出时触发。

<ResponseField name="thread_id" type="string" required>
    会话线程标识符。
</ResponseField>

#### `user.prompt`

在交互模式下用户提交聊天消息时触发。

无额外字段。

#### `input.required`

当智能体需要人工输入时触发（人在回路中断）。

无额外字段。

#### `permission.request`

在审批对话框之前触发，此时一个或多个工具调用需要用户权限。

<ResponseField name="tool_names" type="list[str]" required>
    请求审批的工具名称。
</ResponseField>

#### `tool.error`

当工具调用返回错误时触发。

<ResponseField name="tool_names" type="list[str]" required>
    出错的工具名称。
</ResponseField>

#### `task.complete`

当智能体完成当前任务时触发（流循环结束，不再有进一步中断）。

<ResponseField name="thread_id" type="string" required>
    会话线程标识符。
</ResponseField>

#### `context.compact`

在 Deep Agents Code 压缩（摘要）对话上下文之前触发。

无额外字段。

### 执行模型

- **后台线程**：钩子子进程通过 `asyncio.to_thread` 在线程中运行，因此主事件循环永远不会被阻塞。
- **并发分发**：当多个钩子匹配一个事件时，它们在线程池中并发运行。
- **5 秒超时**：每个命令有 5 秒超时。超过此时间的命令会被终止。
- **即发即弃**：错误按钩子捕获并以调试/警告级别记录。失败的钩子永远不会崩溃或阻塞 Deep Agents Code。
- **懒加载**：配置文件在首次事件分发时读取一次，并在会话剩余时间内缓存。
- **无 shell 展开**：命令直接执行（不通过 shell）。如果需要 shell 功能（如管道或变量展开），请包装在 `["bash", "-c", "..."]` 中。

<Accordion title="Python 处理器">
编写一个处理脚本，从 stdin 读取 JSON 负载：

```python title="my_handler.py"
import json
import sys

payload = json.load(sys.stdin)
event = payload["event"]

if event == "session.start":
    print(f"Session started: {payload['thread_id']}", file=sys.stderr)
elif event == "permission.request":
    print(f"Approval needed for: {payload['tool_names']}", file=sys.stderr)
```

```json title="~/.deepagents/hooks.json"
    {
      "command": ["python3", "my_handler.py"],
      "events": ["session.start", "permission.request"]
    }
  ]
}
```
</Accordion>

### 安全考虑

钩子遵循与 Git 钩子或 shell 别名相同的信任模型——任何能够写入 `~/.deepagents/hooks.json` 的用户都可以执行任意命令。这是设计使然：

- **无命令注入**：负载数据仅通过 stdin 作为 JSON 流入，绝不会流入命令行参数。`json.dumps` 处理转义。
- **默认无 shell**：命令以 `shell=False` 运行，防止 shell 注入。
- **格式错误的配置**：无效 JSON 或意外类型会产生已记录的警告，而非安全问题。

<Warning>
    仅添加来自你信任来源的钩子。钩子具有与你的用户账户相同的权限。
</Warning>
