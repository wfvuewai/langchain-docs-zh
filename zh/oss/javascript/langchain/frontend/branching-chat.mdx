分支对话使用户能够从历史对话中的任何点创建新的对话分支。这对于以下场景特别有用：

- 尝试不同的提示或方法。
- 比较多个 agent 相同输入的响应。
- 从某个点恢复对话而不丢失上下文。

## 何时使用分支

分支在几种场景下很有用：

- **实验**：尝试不同的对话路径而不破坏原始对话。
- **比较**：查看 agent 如何响应不同的输入或配置。
- **恢复**：从对话中的特定点继续，同时保留分支点之前的上下文。

## 它是如何工作的

分支的工作原理是从对话历史中的特定检查点创建新的对话线程。新的线程从该点继承上下文，但独立演化。

分支的实现取决于你如何存储对话历史。

### 通过 API 进行分支

一般来说，分支工作流如下：

1. 用户在 UI 中选择一个历史消息。
2. 前端调用 API 在该点创建新分支。
3. 后端使用该点的上下文初始化新线程。
4. 前端切换到新线程并允许用户继续对话。

## 前端实现

在前端实现分支涉及：

1. **分支选择器**：允许用户选择要分支的历史消息。
2. **分支指示器**：在 UI 中显示当前线程是其一部分的分支。
3. **线程切换**：在原始线程和分支线程之间切换。
4. **上下文保留**：在新分支中保留选定消息之前的对话上下文。
5. **状态管理**：维护准确反映当前分支的线程 ID。

这种方法为用户提供了对话历史的交互式可视化，允许他们自由地分支和探索，同时保持所有路径完好无损并可以恢复。
