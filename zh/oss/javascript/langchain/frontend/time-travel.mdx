---
title: 时间旅行
description: 回溯 agent 执行的历史状态
---

时间旅行使你和你的用户能够回溯 agent 执行历史中的任何点。它对于以下场景特别有用：

- **调试**：检查 agent 在特定时间点所做的确切决策。
- **恢复**：从错误或偏离预期路径的情况中恢复。
- **审核**：审查 agent 在交互每个步骤采取的行动。

## 它是如何工作的

时间旅行使用[检查点](/oss/langgraph/persistence#checkpoints)来捕获 agent 执行每个步骤后的完整状态快照。然后，这些检查点允许你"时间旅行"回到任何状态，并从该确切点恢复执行。

时间旅行的关键方面：

- 每个 agent 执行步骤都会创建一个检查点。
- 检查点捕获完整的图状态，包括消息、工具结果和中间数据。
- 你可以按时间顺序浏览检查点。
- 从先前的检查点恢复执行会创建一个通往当前状态的新路径，实现分支和恢复。

### 检查点结构

检查点结构包含：

- **线程 ID**：检查点所属对话的唯一标识符。
- **检查点 ID**：检查点本身的唯一标识符。
- **状态**：该时间点的完整图状态。
- **时间戳**：创建检查点时的时间。
- **父检查点**：前一个检查点的 ID（用于遍历）。

## 时间旅行如何在前端工作

以下是概念性的 API 端点在时间旅行工作流中的一般交互方式：

1. **获取检查点列表：** 前端请求给定线程的所有可用检查点列表。
2. **选择检查点：** 用户从列表中选择一个检查点，或者选择 UI 重新呈现的状态。
3. **检索状态：** 前端加载与所选检查点关联的状态。
4. **恢复或分支：** 用户可以：

   - **恢复**：从该点继续前进（通常通过发送另一条消息）。
   - **分支**：从该点创建一个新线程，在保留分支历史的同时允许独立的进化。

以下是概念性的 API 工作流：

```python
# 概念性的 API 端点
@app.get("/threads/{thread_id}/checkpoints")
async def list_checkpoints(thread_id: str):
    """列出线程的所有检查点。"""
    return {"checkpoints": [...]}
```

## 选择正确的检查点

从 UI 的角度来看，选择正确的检查点对于良好的用户体验很重要。以下是在时间旅行对话时应该呈现的一些选项：

### 按消息选择

最直观的方法是让用户点击对话中的任何消息。与该消息关联的检查点是由 agent 处理该消息后的状态。

### 按时间线选择

时间线视图显示 agent 执行的所有步骤，包括模型调用和工具执行，允许用户跳转到执行的任何步骤。

### 分支选择器

如果已有分支，用户可以查看可用的分支并选择要探索哪一个。每个分支在其创建后都有独立的执行历史。
