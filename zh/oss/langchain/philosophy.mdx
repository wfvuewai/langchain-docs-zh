LangChain 由几个核心理念驱动：

- 大语言模型 (LLM) 是优秀且强大的新技术。
- 当 LLM 与外部数据源结合时，会变得更加强大。
- LLM 将改变未来应用的面貌。具体来说，未来的应用将变得越来越具有智能体特性。
- 这场变革仍处于非常早期的阶段。
- 虽然构建这些智能体应用的原型很容易，但构建足够可靠并能投入生产的智能体仍然非常困难。

如今开发者可以选择如何构建智能体：使用 [LangChain](/oss/langchain/overview) 获得最大的灵活性和控制力，或者使用 [Deep Agents](/oss/langchain/overview) —— 它提供类似的灵活性和控制力，但带有自带的规划、文件系统工具、子智能体和上下文管理。两者都构建在 [LangGraph](/oss/langgraph/overview) 之上。

对于 LangChain，我们有两个核心关注点：

<Steps>
    <Step title="我们希望让开发者能够使用最好的模型进行构建。">
        不同的提供商暴露了不同的 API，具有不同的模型参数和不同的消息格式。
        标准化这些模型输入和输出是我们的核心关注点，使开发者能够轻松切换到最新、最先进的模型，避免锁定。
    </Step>
    <Step title="我们希望让模型能够轻松编排更复杂的流程，以与其他数据和计算进行交互。">
        模型的应用不应仅限于*文本生成*——它们还应被用于编排更复杂的流程，与其他数据进行交互。LangChain 使定义 LLM 可以动态使用的[工具](/oss/langchain/tools)变得简单，同时也帮助解析和访问非结构化数据。
    </Step>
</Steps>

## 发展历程

鉴于该领域不断变化的节奏，LangChain 也在不断演进。以下是 LangChain 多年来如何演变的简要时间线，与 LLM 构建方式的演变同步：

<Update label="2022-10-24" description="v0.0.1">
    在 ChatGPT 发布前一个月，**LangChain 作为 Python 包首次发布**。它包含两个主要组件：

    - LLM 抽象
    - "链"，即为常见用例预定义的计算步骤序列。例如——RAG：先执行检索步骤，再执行生成步骤。

    LangChain 的名称来源于"Language"（如语言模型）和"Chains"（链）。
</Update>

<Update label="2022-12">
    第一批通用智能体被添加到 LangChain 中。

    这些通用智能体基于 [ReAct 论文](https://arxiv.org/abs/2210.03629)（ReAct 代表 Reasoning and Acting，即推理与行动）。它们使用 LLM 生成表示工具调用的 JSON，然后解析该 JSON 以确定调用哪些工具。
</Update>

<Update label="2023-01">
    OpenAI 发布了"Chat Completion"API。

    此前，模型接收字符串并返回字符串。在 Chat Completions API 中，它们演变为接收消息列表并返回一条消息。其他模型提供商也纷纷效仿，LangChain 也随之更新以支持消息列表。
</Update>

<Update label="2023-01">
    LangChain 发布了 JavaScript 版本。

    LLM 和智能体将改变应用的构建方式，而 JavaScript 是应用开发者的语言。
</Update>

<Update label="2023-02">
    **LangChain Inc. 作为一家公司成立**，围绕开源 LangChain 项目。

    主要目标是"让智能智能体无处不在"。团队认识到，虽然 LangChain 是关键组成部分（LangChain 使开始使用 LLM 变得简单），但还需要其他组件。
</Update>

<Update label="2023-03">
    OpenAI 在其 API 中发布了"function calling"功能。

    这使得 API 能够显式生成表示工具调用的负载。其他模型提供商纷纷效仿，LangChain 被更新为使用此方法作为工具调用的首选方式（而非解析 JSON）。
</Update>

<Update label="2023-06">
    **LangSmith 发布**，由 LangChain Inc. 作为闭源平台推出，提供可观测性和评估功能。

    构建智能体的主要问题在于使其可靠，而提供可观测性和评估功能的 LangSmith 正是为解决这一需求而构建的。LangChain 被更新以无缝集成 LangSmith。
</Update>

<Update label="2024-01" description="v0.1.0">
    **LangChain 发布 0.1.0**，这是第一个非 0.0.x 版本。

    行业从原型阶段发展到了生产阶段，因此 LangChain 加强了对稳定性的关注。
</Update>

<Update label="2024-02">
    **LangGraph 作为开源库发布**。

    最初的 LangChain 有两个关注点：LLM 抽象和帮助入门常见应用的高层接口；但它缺少一个允许开发者控制智能体精确流程的底层编排层。于是，LangGraph 应运而生。

    在构建 LangGraph 时，我们总结了构建 LangChain 时的经验教训，并添加了我们发现必要的功能：流式传输、持久化执行、短期记忆、人工介入等。
</Update>

<Update label="2024-10">
    LangGraph 成为构建任何超过单次 LLM 调用的 AI 应用的首选方式。

    随着开发者试图提高其应用的可靠性，他们需要比高层接口提供的更多控制力。LangGraph 提供了这种底层灵活性。LangChain 中大多数链和智能体被标记为已弃用，并附带了迁移到 LangGraph 的指南。在 LangGraph 中仍然保留了一个高层抽象：智能体抽象。它构建在底层 LangGraph 之上，具有与 LangChain 中的 ReAct 智能体相同的接口。
</Update>

<Update label="2025-10-20" description="v1.0.0">
    **LangChain 发布 1.0**，包含两个重大变化：

    1. `langchain` 中所有链和智能体的全面改造。所有链和智能体现在被替换为唯一一个高层抽象：构建在 LangGraph 之上的智能体抽象。这个高层抽象最初创建于 LangGraph，现在只是迁移到了 LangChain。

        :::
        :::js
        对于仍在使用旧版 LangChain 链/智能体且**不想**升级的用户（注意：我们建议你升级），你可以通过安装 `@langchain/classic` 包继续使用旧版 LangChain。

    2. 标准消息内容格式：模型 API 从返回带有简单内容字符串的消息演变为更复杂的输出类型——推理块、引用、服务端工具调用等。LangChain 演进其消息格式以跨提供商标准化这些内容。
</Update>

<Update label="2026-03-15" description="v0.5.3">
    **Deep Agents 发布**，作为一个构建在 LangGraph 之上的开源智能体框架。

    虽然 LangChain 为自定义智能体架构提供了灵活的构建块，但 [Deep Agents](/oss/langchain/overview) 为复杂、长期运行的任务（如研究和编码）提供了一个开箱即用的选项。它增加了内置规划工具、虚拟文件系统（带可插拔后端——内存、磁盘、LangGraph store、沙箱）以及用于上下文隔离的子智能体生成。使用 Deep Agents 可以获得带有预定义工具的更自主的智能体；使用 LangChain 可以获得对智能体架构的完全控制。
</Update>
