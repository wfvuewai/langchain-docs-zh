[MCP（模型上下文协议）](https://modelcontextprotocol.io/)让你能够通过外部服务器（文件系统、API、数据库等）扩展 Deep Agents Code 的工具，而无需修改智能体本身。Deep Agents Code 在启动时连接到 MCP 服务器，发现其工具，并使其与内置工具一起可供智能体使用。

通过向项目中添加 `.mcp.json` 配置文件来添加 MCP 服务器，用于项目级别范围，或在用户级别添加以应用于所有项目。

## 快速开始

本快速开始将 [LangChain 文档 MCP 服务器](https://docs.langchain.com/mcp) 添加到你机器上的每个 Deep Agents Code 会话中。以相同格式替换为任何其他 MCP 服务器的 URL 或 stdio 命令。

<Steps>
    <Step title="创建配置文件" icon="file">

        如果尚不存在，请在用户级别创建 `.mcp.json` 文件，以使该服务器可用于机器上的每个项目，或在项目级别创建。

        <Tabs>
            <Tab title="用户">

                ```bash
                mkdir -p ~/.deepagents
                touch ~/.deepagents/.mcp.json
                ```

                此文件（`~/.deepagents/.mcp.json`）中的服务器可用于此机器上的每个项目。
            </Tab>
            <Tab title="项目">

                ```bash
                touch .mcp.json
                ```

                此文件（`<project>/.mcp.json`）中的服务器可用于此项目。
            </Tab>
            <Tab title="项目（隐藏）">

                ```bash
                mkdir -p .deepagents
                touch .deepagents/.mcp.json
                ```

                此文件（`<project>/.deepagents/.mcp.json`）中的服务器可用于此项目，但保留在仓库根目录之外。
            </Tab>
        </Tabs>

        参见[发现位置](#discovery-locations)了解完整的优先级规则。


    </Step>

    <Step title="添加 MCP 服务器" icon="plug">

        ```json title="~/.deepagents/.mcp.json"
        {
            "mcpServers": {
                "docs-langchain": {
                    "type": "http",
                    "url": "https://docs.langchain.com/mcp"
                }
            }
        }
        ```

        要添加更多服务器，请向 `mcpServers` 添加更多条目。参见[配置格式](#configuration-format)了解 OAuth、stdio、SSE 和 HTTP 服务器字段、环境变量和标头。
    </Step>

    <Step title="启动 Deep Agents Code" icon="terminal">
        ```bash
        dcode
        ```

        启动时，Deep Agents Code 自动发现配置，连接到每个服务器，发现其工具，并打印确认信息：

        ```
        ✓ 已加载 3 个 MCP 工具
        ```

        在交互会话中运行 `/mcp` 查看每个服务器的状态、传输方式和加载的工具列表。智能体现在可以在会话期间使用这些工具——stdio 服务器在工具调用之间保持活动状态。
    </Step>
</Steps>

## 自动发现

Deep Agents Code 自动在标准位置搜索 `.mcp.json` 文件。无需标志——只需放置配置文件即可被识别。

### 发现位置

配置按此顺序检查（从低到高优先级）：

| 优先级 | 位置 | 范围 |
|--------|------|------|
| 1（最低） | `~/.deepagents/.mcp.json` | 用户级别——适用于所有项目 |
| 2 | `<project>/.deepagents/.mcp.json` | 项目级别——`.deepagents` 子目录 |
| 3（最高） | `<project>/.mcp.json` | 项目级别——根目录（与 Claude Code 兼容） |

项目根目录是最近的包含 `.git` 文件夹的父目录，回退到当前工作目录。

当存在多个配置文件时，它们的 `mcpServers` 条目会被合并。如果同一服务器名称出现在多个文件中，则更高优先级的配置胜出。这允许项目级别配置覆盖用户级别的条目（例如，固定同一服务器的不同版本），而不会影响你的其他项目。

### 标志

| 标志 | 行为 |
|------|------|
| `--mcp-config PATH` | 添加显式配置作为最高优先级源（在自动发现的配置之上合并） |
| `--no-mcp` | 完全禁用 MCP——不加载任何服务器 |

<Note>
    `--mcp-config` 和 `--no-mcp` 是互斥的。
</Note>

### Claude Code 兼容性

如果你已经在项目根目录中为 Claude Code 创建了 `.mcp.json`，Deep Agents Code 会自动识别它——无需额外设置。

## 配置格式

`mcpServers` 下的每个键是一个服务器名称。服务器的字段确定 Deep Agents Code 如何连接到它。

### stdio 服务器（默认）

stdio 服务器作为子进程启动。Deep Agents Code 通过 stdin/stdout 与其通信。

```json title="mcp-config.json"
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"],
      "env": {}
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "your-token" }
    }
  }
}
```

### SSE 和 HTTP 服务器

对于远程 MCP 服务器，将 `type` 设置为 `"sse"` 或 `"http"` 并提供 `url`：

```json title="mcp-config.json"
{
  "mcpServers": {
    "remote-api": {
      "type": "sse",
      "url": "https://api.example.com/mcp",
      "headers": { "Authorization": "Bearer your-token" }
    }
  }
}
```

### 字段参考

        </ResponseField>

    <Accordion title="sse">
        **必需：** `type: "sse"`、`url`。**可选：** `headers`、`auth`，加上共享的[工具过滤字段](#tool-filtering)。

        <ResponseField name="url" type="string" required>

        </ResponseField>

        <ResponseField name="headers" type="object">

        </ResponseField>

        <ResponseField name="auth" type='"oauth"'>
            设置为 `"oauth"` 以使用 `dcode mcp login` 驱动 OAuth 登录流程，而不是提供 `Authorization` 标头。不能与 `Authorization` 标头一起使用。参见 [OAuth 登录](#oauth-login)。
        </ResponseField>

<Note>
    `type` 字段也可以写为 `transport`，以便与其他 MCP 客户端兼容。
</Note>

<Note>
    服务器名称必须匹配 `[A-Za-z0-9_-]+`。名称用作 OAuth 令牌文件的磁盘基础名称，因此在配置加载时会拒绝路径分隔符和其他 shell 元字符。
</Note>

### 标头环境变量

标头值支持来自父 shell 的 `${VAR}` 替换，在服务器激活时解析，而非配置加载时。一个未设置的变量仅使需要它的那个服务器失败；其余服务器仍然启动。

```json title=".mcp.json"
{
    "mcpServers": {
        "internal-api": {
            "type": "http",
            "url": "https://api.example.com/mcp",
            "headers": { "Authorization": "Bearer ${INTERNAL_API_TOKEN}" }
        }
    }
}
```

## 多服务器

你可以根据需要配置任意数量的服务器。所有服务器的工具都会被合并，智能体可以使用：

```json title="mcp-config.json"
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/home/user/projects"]
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "ghp_..." }
    },
    "database": {
      "type": "sse",
      "url": "https://db-mcp.internal:8080/mcp",
      "headers": { "Authorization": "Bearer ..." }
    }
  }
}
```

## 工具过滤

每个服务器可以使用两个可选字段之一来缩小其向智能体公开的工具范围：

- `allowedTools`：仅保留列出的工具；丢弃其他所有工具。
- `disabledTools`：丢弃列出的工具；保留其他所有工具。

过滤适用于 stdio、HTTP 和 SSE 服务器。以下两种情况在配置加载时都会被拒绝：

- 在同一服务器上同时设置 `allowedTools` 和 `disabledTools`。
- 将任一字段设置为空列表（会静默剥离每个工具，或是空操作）。而是省略该字段。

```json title=".mcp.json"
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"],
      "allowedTools": ["read_file", "list_directory"]
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "disabledTools": ["delete_repository", "delete_*_branch"]
    }
  }
}
```

### 匹配规则

每个条目是一个文字工具名称或一个 [`fnmatch`](https://docs.python.org/3/library/fnmatch.html) 风格的 glob（任何包含 `*`、`?` 或 `[` 的条目都被视为模式）。条目会与裸 MCP 工具名称和服务器前缀形式（`{server}_{tool}`）进行匹配，因此两种形式都有效：

```json
{
  "allowedTools": ["read_file", "fs_list_*"]
}
```

<Note>
    匹配不到任何已加载工具的条目会记录为警告，而非错误——底层 MCP 服务器可以跨版本演进而不会破坏你的配置。
</Note>

<ResponseField name="allowedTools" type="string[]">
    要保留的工具名称或 `fnmatch` glob 模式。此服务器的所有其他工具被丢弃。与 `disabledTools` 互斥。
</ResponseField>

<ResponseField name="disabledTools" type="string[]">
    要丢弃的工具名称或 `fnmatch` glob 模式。此服务器的所有其他工具被保留。与 `allowedTools` 互斥。
</ResponseField>

## OAuth 登录

对于需要 OAuth 的远程 MCP 服务器（Slack、GitHub、Notion、Linear 和其他托管的 MCP 端点），在服务器条目上设置 `"auth": "oauth"` 并运行一次登录子命令。令牌将持久化到磁盘并自动刷新。

### 配置服务器

```json title=".mcp.json"
{
    "mcpServers": {
        "linear": {
            "type": "http",
            "url": "https://mcp.linear.app/mcp",
            "auth": "oauth"
        }
    }
}
```

`auth: "oauth"` 与同一条目上的 `Authorization` 标头互斥，且不能在 stdio 服务器上设置。

### 运行登录流程

```bash
dcode mcp login linear
```

具体行为取决于服务器的主机：

- **符合规范的服务器**（默认）：Deep Agents Code 执行动态客户端注册，在浏览器中打开授权码 + PKCE 流程，并要求你将重定向 URL 粘贴回终端。
- **Slack**（`slack.com`、`*.slack.com`）：相同的粘贴回流程，但预填了 Slack 的公共客户端。你会被提示输入可选的团队 ID（例如 `T01234567`），以便应用安装到正确的工作空间。
- **GitHub**（`api.githubcopilot.com`）：RFC 8628 设备授权授权。Deep Agents Code 打印验证 URL 和用户代码；你在浏览器中输入代码，Deep Agents Code 轮询完成情况。

默认情况下，`dcode mcp login` 读取与 Deep Agents Code 运行时相同的自动发现配置（受项目级别信任门控）。传递 `--config <path>` 使用特定文件：

```bash
dcode mcp login linear --config ./mcp-config.json
```

<Warning>
    尚未被信任的项目级别配置（参见[项目级别信任](#project-level-trust)）在 `mcp login` 期间会被跳过，以防止攻击者控制的 `headers` 条目通过 `${VAR}` 插值泄露本地密钥。先在项目中运行一次 `dcode` 以批准配置，或显式传递 `--config <path>`。
</Warning>

### 令牌存储

令牌写入到：

```text
~/.deepagents/.state/mcp-tokens/<server>-<sha256-16(url)>.json
```

`<sha256-16(url)>` 部分是服务器 URL 的 SHA-256 的前 16 个十六进制字符。目录锁定为模式 `0700`，每个令牌文件为模式 `0600`。文件包含 OAuth 访问令牌、刷新令牌和动态注册的客户端信息，全部包含在具有版本号的负载中，原子性地写入（写入临时文件 + `rename`）。

<Note>
    将 URL 哈希到文件名意味着指向不同 URL 的同一服务器名称（例如开发环境与生产环境）会获得独立的令牌文件，不会互相覆盖。
</Note>

### 重新认证

当运行时刷新失败（刷新令牌过期或被撤销）时，Deep Agents Code 将服务器标记为 `unauthenticated`，而不是崩溃智能体。欢迎横幅显示未认证服务器的数量，`/mcp` 按服务器报告原因。重新运行 `dcode mcp login <server>` 刷新凭据——你的对话继续，无需重启。

## 服务器状态

每个配置的服务器在启动后处于三种状态之一：

| 状态 | 含义 |
|------|------|
| `ok` | 已连接；工具已加载并可供智能体使用 |
| `unauthenticated` | 需要 OAuth 登录或刷新失败——运行 `dcode mcp login <server>` |
| `error` | 预检、发现或传输设置失败；附有错误消息 |

单个服务器失败不再中止启动。智能体使用任何正常启动的服务器运行，欢迎横幅会在工具计数旁边显示未认证和出错的服务器数量。在交互会话中打开 `/mcp` 查看每个服务器的状态、传输方式、工具列表和非 `ok` 条目的失败原因。查看器会在服务器连接时实时更新，并支持 `tab`/`shift+tab` 导航。

## 项目级别信任

项目级别配置可能包含执行本地命令的 stdio 服务器，以及其 `headers` 可能从你的环境中插值 `${VAR}` 的远程服务器。为防止不受信任的仓库在 CLI 启动时运行任意代码或泄露本地密钥，Deep Agents Code 对项目级条目强制执行**默认拒绝**策略。

### 工作原理

- **交互模式：** Deep Agents Code 在激活项目服务器前提示批准，显示每个 stdio 命令和远程 URL。批准使用 SHA-256 内容指纹持久化——如果配置更改，你会再次被提示。
- **非交互模式（`-n`）：** 除非传递了 `--trust-project-mcp`，否则项目服务器被静默跳过。
- **信任涵盖 stdio 和远程条目**——远程服务器可以在预检探测期间 SSRF 到 localhost 或云元数据端点，并通过标头泄露 `${VAR}` 值，因此它们与 stdio 以相同方式被门控。
- **用户级别配置**（`~/.deepagents/.mcp.json`）始终受信任——与 `config.toml` 和 `hooks.json` 相同的信任模型。
- **`dcode mcp login`** 也遵循项目信任：不受信任的项目级别配置在登录发现期间被跳过，因此攻击者控制的远程条目无法将密钥拉入 OAuth 握手。

### 标志

| 标志 | 行为 |
|------|------|
| `--trust-project-mcp` | 信任所有项目级别的 stdio 服务器而不提示（用于 CI 和自动化） |

```bash
# 跳过审批提示
dcode --trust-project-mcp

# 非交互模式：显式信任项目服务器
dcode -n "运行测试" --trust-project-mcp
```

### 信任存储

信任决策存储在 `~/.deepagents/config.toml` 中：

```toml
[mcp_trust.projects]
"/Users/you/myproject" = "sha256:abc123..."
```

每个键是一个绝对的项目根路径。值是项目级别配置内容的连接后的 SHA-256 摘要。要撤销信任，删除该条目或修改项目的 `.mcp.json`（这会使指纹自动失效）。

<Warning>
    受信任的 stdio MCP 服务器具有与你的用户账户相同的权限。仅批准来自你信任的仓库的服务器。在接受前，审查批准提示中显示的命令。
</Warning>

## 系统提示感知

连接的 MCP 服务器及其工具会自动列在智能体的系统提示中，按服务器名称和传输类型分组。这有助于模型推理工具来源和故障域，无需手动上下文。

## 故障排除

<AccordionGroup>
    <Accordion title="服务器无法启动（stdio）">
        验证命令在 Deep Agents Code 外部是否正常工作：

        ```bash
        npx -y @modelcontextprotocol/server-filesystem /tmp
        ```

        常见原因：包未安装、`npx` 不在 `PATH` 中，或所需的环境变量缺失。
    </Accordion>

    <Accordion title="连接被拒绝（SSE/HTTP）">
        检查远程服务器是否正在运行且 URL 是否正确。如果服务器需要认证，确保 `headers` 包含正确的凭据。
    </Accordion>

    <Accordion title="工具未出现">
        Deep Agents Code 会在启动时打印加载的工具数量（例如 `✓ 已加载 3 个 MCP 工具`）。如果你看到 `0`，服务器已成功启动但未通告任何工具——检查服务器自身的日志或文档。
    </Accordion>

    <Accordion title="服务器在 /mcp 中显示 `unauthenticated`">
        要么你尚未运行 `dcode mcp login <server>`，要么持久化的刷新令牌在服务器端已过期或被撤销。再次运行登录命令——你的会话保持运行，服务器会在令牌刷新后重新连接。
    </Accordion>

    <Accordion title="`无效的 MCP 配置在 ...`">
        预检验证拒绝了 `--mcp-config`（或自动发现的 `.mcp.json`）。常见原因：不支持的服务器名称（必须匹配 `[A-Za-z0-9_-]+`）、stdio 服务器上的 `auth: oauth`、同一条目上同时设置了 `command` 和 `url`，或标头值不是字符串。修复突出显示的原因并重新启动——Deep Agents Code 不再为配置错误转储多页子进程跟踪。
    </Accordion>

    <Accordion title="`${VAR}` 标头引用失败">
        标头插值在激活时运行，因此未设置的变量仅使需要它的服务器失败。在父 shell 中导出变量，或将其添加到 `~/.deepagents/.env`。要进行调试，设置 `DEEPAGENTS_CODE_DEBUG=1` 并在关闭时检查打印到 stderr 的每次会话日志路径。
    </Accordion>
</AccordionGroup>
