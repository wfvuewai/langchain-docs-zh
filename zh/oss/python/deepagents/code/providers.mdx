Deep Agents Code 支持任何[与 LangChain 兼容的聊天模型提供商](/zh/oss/integrations/chat)，实际上可以使用任何支持工具调用的 LLM。任何公开 OpenAI 兼容或 Anthropic 兼容 API 的服务也可以开箱即用——参见[兼容 API](/zh/oss/deepagents/code/configuration#compatible-apis)。

## 快速开始

Deep Agents Code 自动与[以下模型提供商](#provider-reference)集成：除了安装相关的提供商包外，无需额外配置。

1. **安装提供商包**

    每个模型提供商需要安装其对应的 LangChain 集成包。这些作为安装 Deep Agents Code 时的可选扩展提供，特意保持应用程序轻量：

    ```bash
    # 使用选定的提供商快速安装
    # OpenAI、Anthropic 和 Gemini 默认包含
    DEEPAGENTS_EXTRAS="baseten,groq" curl -LsSf https://langch.in/dcode | bash

    # 或直接使用 uv 安装
    uv tool install 'deepagents-code[baseten,groq]'

    # 在以后添加额外包
    uv tool install deepagents-code --with langchain-ollama

    # 所有提供商
    uv tool install 'deepagents-code[anthropic,baseten,bedrock,cohere,deepseek,fireworks,google-genai,groq,huggingface,ibm,litellm,mistralai,nvidia,ollama,openai,openrouter,perplexity,vertexai,xai]'
    ```

2. **设置凭据**

    将 API 密钥存储在 `~/.deepagents/.env` 中，以便它们对所有项目可用，或在 shell 中导出：

    <Tabs>
        <Tab title="OpenAI">
            <CodeGroup>
                ```bash 永久添加
                mkdir -p ~/.deepagents
                echo 'OPENAI_API_KEY=your-api-key' >> ~/.deepagents/.env
                ```

                ```bash 为当前会话添加
                export OPENAI_API_KEY="your-api-key"
                ```
            </CodeGroup>
        </Tab>
        <Tab title="Anthropic">
            <CodeGroup>
                ```bash 永久添加
                mkdir -p ~/.deepagents
                echo 'ANTHROPIC_API_KEY=your-api-key' >> ~/.deepagents/.env
                ```

                ```bash 为当前会话添加
                export ANTHROPIC_API_KEY="your-api-key"
                ```
            </CodeGroup>
        </Tab>
        <Tab title="Google">
            <CodeGroup>
                ```bash 永久添加
                mkdir -p ~/.deepagents
                echo 'GOOGLE_API_KEY=your-api-key' >> ~/.deepagents/.env
                ```

                ```bash 为当前会话添加
                export GOOGLE_API_KEY="your-api-key"
                ```
            </CodeGroup>
        </Tab>
        <Tab title="其他">
            Deep Agents Code 可与任何支持工具调用的 LLM 配合使用。参见[提供商参考](#provider-reference)获取支持的提供商完整列表及其所需的环境变量。

        </Tab>
    </Tabs>

    要配置模型参数，请参见[模型参数](/zh/oss/deepagents/code/providers#model-parameters)。

    你也可以使用 [`DEEPAGENTS_CODE_` 前缀](/zh/oss/deepagents/code/configuration#deepagents_code_-prefix)将凭据限定在 Deep Agents Code 范围内。

| LiteLLM | [`langchain-litellm`](/zh/oss/integrations/chat/litellm) | `litellm:<model>`（内置，参见[提供商参考](#provider-reference)） |
:::

| 路由器 | 包 |
| --- | --- |
| OpenRouter | [`langchain-openrouter`](/zh/oss/integrations/chat/openrouter) |

```bash
uv tool install 'deepagents-code[openrouter]'
```

**LiteLLM** 也是一个内置提供商：

```bash
uv tool install 'deepagents-code[litellm]'
```

## 切换模型

要在 Deep Agents Code 中切换模型，可以：

1. **使用交互式模型切换器**，通过 `/model` 命令。这显示来自每个已安装 LangChain 提供商包的[模型配置文件](/zh/oss/langchain/models#model-profiles)的可用模型。

    <Note>
        并非所有模型都出现在此处。如果你的模型缺失，请直接传递模型名称（例如 `/model gpt-5.5`）。参见[哪些模型出现在切换器中](#which-models-appear-in-the-switcher)了解详情。
    </Note>
2. **直接指定模型名称**作为参数，例如 `/model gpt-5.5`。你可以使用所选提供商支持的任何模型，无论它是否出现在选项 1 的列表中。模型名称将传递给 API 请求。
3. **在启动时通过 `--model` 指定模型**，例如

    ```txt
    dcode --model openai:gpt-5.5
    ```

<Accordion title="模型解析顺序" icon="list-numbers">
    当 Deep Agents Code 启动时，它按以下顺序解析要使用的模型：

    1. **`--model` 标志**在提供时始终胜出。
    2. **`[models].default`** 在 `~/.deepagents/config.toml` 中——用户的明确长偏好。
    3. **`[models].recent`** 在 `~/.deepagents/config.toml` 中——上次通过 `/model` 切换到的模型。自动写入；从不覆盖 `[models].default`。
    4. **环境自动检测**：回退到第一个可用的启动凭据，按以下顺序检查：`OPENAI_API_KEY`、`ANTHROPIC_API_KEY`、`GOOGLE_API_KEY`、`GOOGLE_CLOUD_PROJECT`（Vertex AI）。

    此启动回退仅检查这四个凭据。其他支持的提供商（例如 Groq）仍然可以通过 `--model`、`/model` 和保存的默认值（`[models].default` / `[models].recent`）使用。
</Accordion>

### 哪些模型出现在切换器中

`/model` 选择器从已安装的提供商包动态构建其列表。展开下方查看完整标准和故障排除。

<Accordion title="切换器如何构建其模型列表" icon="list-search">
    交互式 `/model` 选择器动态构建其列表——它不是 Deep Agents Code 中硬编码的列表。当**所有**以下条件为真时，模型会出现在切换器中：

    1. **提供商包已安装。** 每个提供商（例如 `langchain-anthropic`、`langchain-openai`）必须与 `deepagents-code` 一起安装——作为[安装扩展](/zh/oss/deepagents/code/providers#quickstart)（例如 `uv tool install 'deepagents-code[ollama]'`）或稍后使用 `uv tool install deepagents-code --with <package>` 添加。如果包缺失，则其整个提供商部分都不会出现在切换器中。
    2. **模型具有启用了 `tool_calling` 的配置文件。** Deep Agents Code 需要工具调用支持，因此配置文件中没有 `tool_calling: true` 的模型会被排除。这是模型从列表中缺失的最常见原因。对于不捆绑配置文件的提供商（参见[提供商参考](#provider-reference)表格），你可以在 `config.toml` 中定义一个：

        ```toml
        [models.providers.ollama.profile."qwen3:4b"]
        tool_calling = true
        max_input_tokens = 32768
        max_output_tokens = 8192
        ```

        这对于模型出现在切换器中并非严格必需——将其添加到 [`models` 列表](/zh/oss/deepagents/code/configuration#adding-models-to-the-interactive-switcher)也有效且更简单。当你希望 Deep Agents Code 了解模型的上下文窗口和能力以用于自动摘要等功能时，配置文件很有用。参见[配置文件覆盖](/zh/oss/deepagents/code/configuration#profile-overrides-advanced)了解所有可覆盖的字段。
    3. **模型接受并产生文本。** 配置文件中显式将 `text_inputs` 或 `text_outputs` 设置为 `false` 的模型（例如嵌入或图像生成模型）会被排除。

    在 `config.toml` 的 [`[models.providers.<name>].models`](/zh/oss/deepagents/code/configuration#adding-models-to-the-interactive-switcher) 下定义的模型会绕过配置文件过滤器——无论配置文件元数据如何，它们始终出现在切换器中。这是添加列表中缺失模型的推荐方式。

    <Tip>
        凭据状态**不**影响模型是否被列出。切换器显示所有符合条件的模型，并在每个提供商标头旁边显示凭据指示器：已确认凭据的打勾，缺失凭据的警告，或凭据状态未知的问号。你仍然可以选择具有缺失凭据的模型——提供商会报告请求时的认证错误。
    </Tip>

    #### 缺失模型故障排除

    | 症状 | 可能原因 | 修复 |
    | --- | --- | --- |
    | 切换器中整个提供商缺失 | 提供商包未安装 | 安装包（例如 `uv tool install deepagents-code --with langchain-groq`） |
    | 提供商已显示但特定模型缺失 | 模型配置文件中 `tool_calling: false` 或不存在配置文件 | 将模型添加到 `config.toml` 的 `[models.providers.<name>].models` 中，或直接使用 `/model <provider>:<model>` |
    | 提供商显示 ⚠ "凭据缺失" | API 密钥环境变量未设置 | 从[提供商参考](#provider-reference)表格中设置凭据环境变量 |
    | 提供商显示 ? "凭据未知" | 提供商使用 Deep Agents Code 无法验证的非标准认证 | 凭据可能仍然有效——尝试切换到该模型。如果认证失败，请检查提供商的文档 |
</Accordion>

### 设置默认模型

你可以设置一个持久的默认模型，用于所有未来的 CLI 启动：

* **通过模型选择器：** 打开 `/model`，导航到所需模型，然后按 `Ctrl+S` 将其固定为默认值。在当前默认值上再次按 `Ctrl+S` 会清除它。
* **通过命令：** `/model --default provider:model`（例如 `/model --default anthropic:claude-opus-4-7`）
* **通过配置文件：** 在 `~/.deepagents/config.toml` 中设置 `[models].default`（参见[配置](/zh/oss/deepagents/code/configuration)）。
* **从 shell：**

    ```bash
    dcode --default-model anthropic:claude-opus-4-7
    ```

要查看当前默认值：

```bash
dcode --default-model
```

要清除默认值：

* **从 shell：**

    ```bash
    dcode --clear-default-model
    ```

* **通过命令：** `/model --default --clear`
* **通过模型选择器：** 在当前固定的默认模型上按 `Ctrl+S`。

没有默认值时，Deep Agents Code 将默认使用最近使用的模型。

### 模型参数

向模型传递额外的构造函数 kwargs——采样控制、推理/思考预算、上下文窗口大小、请求超时以及底层聊天模型类接受的任何其他参数。按优先级顺序（最高优先）有三种设置位置：

1. **启动时一次性使用 `--model-params`。** JSON 字符串，仅会话有效：

    ```bash
    # OpenAI 推理力度
    dcode --model openai:gpt-5.5 --model-params '{"reasoning": {"effort": "high"}}'

    # Anthropic 扩展思考
    dcode --model anthropic:claude-opus-4-7 --model-params '{"thinking": {"type": "enabled", "budget_tokens": 10000}, "max_tokens": 16000}'
    ```

2. **会话中通过 `/model --model-params`。** 相同的 JSON 语法——无需重启即可交换参数（以及可选地交换模型）：

    ```txt
    /model --model-params '{"temperature": 0.7}' anthropic:claude-opus-4-7
    /model --model-params '{"num_ctx": 16384}'           # 打开选择器，将参数应用于选择
    ```

3. **持久化在 `config.toml` 中。** 提供商级别的默认值（带有可选的按模型子表），在每次启动时应用：

    ```toml
    [models.providers.anthropic.params]
    thinking = { type = "enabled", budget_tokens = 10000 }
    max_tokens = 16000

    [models.providers.openai.params]
    reasoning = { effort = "high", summary = "auto" }
    output_version = "responses/v1"

    [models.providers.ollama.params]
    num_ctx = 16384
    temperature = 0

    # 按模型覆盖——胜于提供商级别键
    [models.providers.ollama.params."qwen3:4b"]
    temperature = 0.5
    ```

CLI 标志覆盖配置文件 `params` 且仅会话有效（会话中的更改不会持久化）。`config.toml` 中的按模型子表覆盖提供商级别键（浅合并——参见[模型构造函数参数](/zh/oss/deepagents/code/configuration#model-constructor-params)了解完整语义）。`--model-params` 不能与 `--default` 结合使用。

<Tip>
    底层聊天模型构造函数接受的任何 kwargs 都是有效的。请参阅提供商的参考文档获取完整列表——例如 [`ChatAnthropic`](https://reference.langchain.com/python/langchain-anthropic/langchain_anthropic/chat_models/ChatAnthropic)、[`ChatOpenAI`](https://reference.langchain.com/python/langchain-openai/langchain_openai/chat_models/base/ChatOpenAI)、[`ChatOllama`](https://reference.langchain.com/python/langchain-ollama/langchain_ollama/chat_models/ChatOllama)。未知的 kwargs 会转发到上游 API 请求，因此新发布的参数无需 CLI 更新即可使用。
</Tip>

<Note>
    不要将凭据（`api_key`）放在 `params` 中——使用 [`api_key_env`](/zh/oss/deepagents/code/configuration#provider-configuration) 指向环境变量。
</Note>

要覆盖模型运行时*配置文件*上的字段（`max_input_tokens`、`tool_calling`、能力标志）——与构造函数参数不同——请参见[配置文件覆盖](/zh/oss/deepagents/code/configuration#profile-overrides-advanced)。
