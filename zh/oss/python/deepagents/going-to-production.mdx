## 概述

将深度代理投入生产需要解决配置、可观测性、多租户和安全方面的挑战。

深度代理的生产部署通常涉及以下组件：

1. **代理服务器**——作为管理请求、线程和运行的中央入口点。
2. **沙箱**——为代码执行提供隔离环境的后端。
3. **存储（持久化）**——持久化代理状态、运行时历史和已存储对象的数据库。
4. **模型提供商**——为代理提供支持的底层 LLM API。
5. **可观测性**——用于监控、调试和评估代理性能的工具。

## 配置管理

将配置管理视为代码问题。

### 环境变量

对敏感值使用环境变量：

```python
import os

agent = create_deep_agent(
    model=os.getenv("DEFAULT_MODEL", "google_genai:gemini-3.5-flash"),
    api_key=os.getenv("LLM_API_KEY"),
)
```

### 配置档案

在生产中拥有多个环境（暂存、生产、测试）和模型配置。在部署过程中将配置注册为配置档案，使其可切换。

## Webhook 和自动化

LangSmith 代理服务器支持 webhooks，你可以使用它们订阅代理事件。典型的 webhook 用例：

- 将长时间运行的任务结果通知外部服务。
- 审计或日志系统。
- CI/CD 流水线触发。

## 可观测性

在生产中调试代理行为需要适当的可观测性。

### 追踪

深度代理自动与 LangSmith 集成以进行追踪。通过追踪，你可以检查：

- **延迟细分**：工具调用花了多长时间？
- **令牌使用**：每个节点使用了多少令牌？
- **错误追踪**：失败发生在哪里？
- **代理流程**：代理决策流程是什么？

### 评估

评估是保持生产代理质量的关键。LangSmith 提供了用于评估代理输出的工具，包括数据集和测试。

### 监控

设置监控以跟踪：

- **调用量**：按时间、模型或工具划分。
- **错误率**：全局或按模型提供商划分。
- **延迟**：第 50、95 和 99 百分位。
- **令牌使用**：输入和输出令牌计数。
- **成本**：按模型提供商或用途聚合。

## 多租户

生产部署通常为多个用户提供服务。深度代理通过作用域线程支持多租户，确保数据完全隔离。

### 生命周期

沙箱可以通过两种方式与代理服务器关联：
- **一个沙箱对应一个用户 ID**：共享沙箱在所有线程和用户之间共享，适合共享安装的包环境。
- **一个沙箱对应一个助手 ID**：每个助手（由代理服务器定义）都有自己的沙箱。

### 按用户隔离

要对每个最终用户的数据进行隔离，按用户作用域进行划分。每个用户都在自己的上下文中运行，由线程 ID 分隔。这可以为每个用户启动一个单独的沙箱。

### 团队访问控制（RBAC）

代理服务器支持角色基础访问控制。你可以定义细粒度的角色来控制谁可以创建、读取、更新或删除代理、线程和运行。

## 生产注意事项

### 速率限制

为 LLM API 调用实施速率限制以防止成本激增：

```python
agent = create_deep_agent(
    model="openai:gpt-5.4",
    max_concurrent_requests=10,
    rate_limit_per_minute=100,
)
```

### 错误处理

为所有外部服务调用实施重试逻辑：

```python
agent = create_deep_agent(
    model="openai:gpt-5.4",
    max_retries=3,
    retry_on_failure=True,
)
```

### 超时

设置超时以防止无限运行：

```python
agent = create_deep_agent(
    model="openai:gpt-5.4",
    max_execution_time_seconds=300,
    tool_call_timeout_seconds=60,
)
```

### 成本管理

使用 LangSmith 追踪来：
- 按用户追踪令牌使用。
- 设置按用户或全局的每月预算。
- 为高成本模型实施模型路由。
- 监控成本异常并设置警报。
