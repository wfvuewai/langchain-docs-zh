---
title: 前端人工介入
description: 在 agent 工具执行前暂停等待审批
---

AI agent 有时会在继续之前需要人类的批准。[Human-in-the-loop](/oss/langchain/concepts/human-in-the-loop)（HITL）模式在 agent 准备执行高风险工具调用（例如发送邮件或写入数据库）时暂停执行，等待人工输入。

## 前端如何与 HITL 交互

当 agent 调用受保护的函数时，它会抛出一个 `HumanEvaluation` 异常。你的前端需要：

1. **捕获异常**：拦截来自 agent 后端的响应，查找 `HumanEvaluation` 错误。
2. **向用户展示**：显示待处理的工具调用，并显示批准或拒绝的按钮。
3. **发送响应**：通过 API 将用户的决定发送回 agent。

## HITL 消息类型

HITL 交互涉及三种类型的消息：

| 类型 | 方向 | 内容 |
|------|----------|---------|
| 工具请求 | agent → UI | 需要审批的工具调用详细信息。状态为 `requires_input`。 |
| 人工响应 | UI → agent | 用户的决定（批准、编辑或拒绝）。 |
| 工具结果 | agent → UI | 最终结果（执行或拒绝）。 |

## 错误处理

当工具调用触发 HITL 中断时，agent 后端会引发一个错误。你的前端应该：

1. 捕获错误。
2. 识别需要审批的工具调用。
3. 向用户显示明确的选项（批准/编辑/拒绝）。
4. 将用户的选择发送回 agent。

### 示例错误响应

```json
{
  "error": "human_evaluation_required",
  "tool_call": {
    "id": "call_123",
    "name": "send_email",
    "args": {
      "to": "user@example.com",
      "subject": "Hello",
      "body": "World"
    }
  },
  "options": ["approve", "edit", "reject"]
}
```

## HITL 交互的前端模式

以下是将 HITL 集成到前端应用中的一般模式：

### 基本集成

**1. 发起 agent 请求：**
前端发送用户消息并立即将状态设置为等待 HITL（或完成）。

**2. 检查 HITL 响应：**
如果在流中收到异常/错误，解析工具调用详情。

**3. 呈现 UI：**
将工具调用渲染为可操作的卡片，并提供明确的选项（批准、编辑、拒绝）。

**4. 处理用户选择：**
通过将用户的决定发送回 agent 端点来恢复执行。

### 带编辑功能的 HITL

如果用户选择"编辑"，前端会提示用户修改工具参数。这使得 UI 流程变为：

1. 显示工具调用详情。
2. 用户选择"编辑"。
3. 显示允许编辑的参数表单。
4. 用户修改参数并提交。
5. 带有更新后参数的恢复请求已发送。

### 通过 WebSocket 进行流式处理

对于实时应用，WebSocket 提供了更好的体验：

- Agent 发送流式事件，包括 HITL 中断事件。
- 前端立即显示待处理的工具调用。
- 用户点击批准或编辑，响应通过 WebSocket 发送回。
- Agent 流式传输工具结果和后续的 AI 响应。

## 前端安全

实施 HITL 时：

- **始终显示明确的工具调用详细信息**，包括参数和值。
- **需要用户确认**高风险操作（例如，输入"CONFIRM"）。
- **验证权限**，确保只有授权用户可以批准工具调用。
- **记录所有 HITL 决策**，用于审计跟踪。

有关更多详细信息和配置选项，请参阅 [Human-in-the-loop middleware](/oss/langchain/middleware/built-in#human-in-the-loop) 文档。
